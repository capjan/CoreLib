# Migration to CoreLib 13.0

[Documentation home](../README.md)

CoreLib 13.0 removes the custom logging implementation in `Core.Logging`. Use the standard Microsoft logging abstractions instead. They let a library emit logs through the host application's configured providers without defining a second logger API or managing process-wide targets.

The package targets `net10.0` and `netstandard2.0`; the `net8.0` target has been removed. Applications on .NET 10 use the native target, while older compatible runtimes can use the `netstandard2.0` target.

Add a reference to `Microsoft.Extensions.Logging.Abstractions` to a library that needs to log, then accept an `ILogger<TCategoryName>` from the application:

```csharp
using Microsoft.Extensions.Logging;

public sealed class Worker(ILogger<Worker> logger)
{
    public void Run()
    {
        logger.LogInformation("Worker {WorkerName} started", nameof(Worker));
    }
}
```

The application configures the logging providers and injects the logger. For guidance, see [Logging in .NET](https://learn.microsoft.com/dotnet/core/extensions/logging) and [Logging guidance for .NET library authors](https://learn.microsoft.com/dotnet/core/extensions/logging/library-guidance).

`Core.IO.Impl.DefaultTempUtil` no longer catches and logs exceptions from its `UseDir` and `UseFile` callbacks. Callback exceptions propagate while cleanup is attempted in `finally`.

Other behavior corrections:

* `DefaultFileUtil.Touch` no longer truncates an existing file.
* Temporary directories are deleted recursively when a `UseDir` callback finishes.
* `DefaultPublicIpResolver` only returns a value that matches an IPv4 address.
* `CliWrapper` now enforces its timeout and throws `TimeoutException` when the process exceeds it.

The downloader and public IP resolver have additive asynchronous interfaces with cancellation support. Existing synchronous interfaces remain available during this migration period.
